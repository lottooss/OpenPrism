# OpenPrism Canonical Bus Contract v1

## 1. Overview & Architecture

The OpenPrism Canonical Bus defines the message schemas and normative semantics connecting perception, tracking, prediction, aim policy, trajectory planning, actuation, and telemetry.

All messages crossing module or process boundaries are serialized using FlatBuffers schemas located under `schemas/bus/`. The released wire contract is bus schema major version 1; “v1” does not refer to the FlatBuffers compiler version.

The repository pins FlatBuffers/`flatc` 25.12.19 through `vcpkg.json` and `python/uv.lock`. Generated C++ headers live under `generated/flatbuffers/cpp/`; generated Python modules and stubs live under `python/aim/bus/v1/`. These files must never be edited by hand.

## 2. File Identifiers and Magic Tokens

Each canonical message type possesses a 4-byte magic file identifier embedded at byte offset 4–7 of the FlatBuffers binary layout:

| Message Type | Root Table | File Identifier | Extension | Schema Source |
|---|---|---|---|---|
| Frame Lease | `FrameDescriptor` | `AFR1` | `.afr` | `schemas/bus/frame_descriptor.fbs` |
| Target Observations | `TargetObservationBatch` | `AOB1` | `.aob` | `schemas/bus/target_observation.fbs` |
| Tracked Targets | `TrackedTargetBatch` | `ATT1` | `.att` | `schemas/bus/tracked_target.fbs` |
| Aim Intent | `AimIntent` | `AAI1` | `.aai` | `schemas/bus/aim_intent.fbs` |
| Actuation Command | `ActuationCommand` | `AAC1` | `.aac` | `schemas/bus/actuation_command.fbs` |
| Telemetry Event | `HotLoopTelemetryEvent` | `ATE1` | `.ate` | `schemas/bus/telemetry_event.fbs` |

## 3. Normative Semantics

### 3.1 Time Semantics
- All timestamps (`source_timestamp_ns`, `captured_at_ns`, `published_at_ns`, `desired_apply_time_ns`) represent signed 64-bit monotonic nanoseconds derived from `QueryPerformanceCounter` (`IClock::now_ns()`).
- Wall-clock time (`gettimeofday`, UTC, system time) is strictly forbidden on the hot path.
- Invariant: `captured_at_ns <= published_at_ns <= desired_apply_time_ns`.

### 3.2 Coordinate Systems
- **Pixel Coordinates (`Vec2f`, `BBoxf`)**:
  - Origin `(0, 0)` is the top-left of the source display frame.
  - `+x` points right; `+y` points down.
  - Units are pixels in the native resolution (e.g. 1920×1080).
- **Normalized Coordinates (`Vec2f center_norm`)**:
  - Origin `(0, 0)` is the exact center of the capture surface.
  - Domain is `[-1.0, 1.0]` along each axis.
  - `+x` points right; `+y` points down.
- **Velocities & Accelerations**:
  - Velocities are expressed in pixels per second (`px/s`).
  - Accelerations are expressed in pixels per second squared (`px/s²`).
- **Covariance**:
  - Symmetric 2D error covariance (`xx`, `xy`, `yy`) in `pixels²`.

### 3.3 Correlation & Tracing
Every message table embeds a `CorrelationHeader`:
- `sequence_id`: Strictly monotonic 64-bit integer incremented per capture frame.
- `source_timestamp_ns`: Monotonic timestamp when the frame surface arrived from DXGI/WGC.
- `pipeline_run_id`: Unique execution session identifier.
- `flags`: Bitmask encoding diagnostic states (`Synthetic = 1`, `Warmup = 2`, `Dropped = 4`, `TraceVerbose = 8`).

## 4. Schema Evolution Policy

The bus adheres to strict additive evolution rules defined by FlatBuffers:
1. **Major Version (e.g., v1 -> v2)**:
   - Changes that remove fields, alter enum ordinal mappings, or change semantic coordinate conventions require a major version bump, an ADR, and an adapter.
2. **Minor Additive Changes**:
   - New fields may be added only to the end of tables with explicit default values.
   - Existing fields must NEVER be removed, renamed, or repurposed.
3. **Automated Conformance Checking**:
   - CI validates schema backward-compatibility using `flatc --conform <released_v1.fbs> <candidate.fbs>`.
4. **Golden Message Verification**:
   - Golden binary test messages generated by release versions are verified to decode identically in C++ and Python test suites.

## 5. Code Generation and Conformance

Configure the pinned vcpkg manifest first so `flatc.exe` exists, then run:

```powershell
cmake --preset windows-msvc-debug
./scripts/generate-bus-bindings.ps1
./scripts/generate-bus-bindings.ps1 -Check
./scripts/check-bus-schema-conformance.ps1
```

`generate-bus-bindings.ps1` rejects any compiler other than 25.12.19. Check mode regenerates into an ignored staging directory and compares the complete generated C++/Python file sets and SHA-256 hashes without changing tracked outputs.

`check-bus-schema-conformance.ps1` runs `flatc --conform` for each of the seven canonical schemas against `schemas/bus/released/v1/`, using separate include roots for the released and current `common.fbs`. A change is acceptable only when all seven comparisons pass.

The CTest target `aim_bus_schema_cross_language_test` provides bidirectional evidence rather than two same-language round trips:

1. generated Python builders emit an `AFR1` `FrameDescriptor`;
2. generated C++ bindings verify and decode it;
3. generated C++ builders emit an `AAC1` `ActuationCommand`;
4. generated Python bindings decode and validate the result.

Both sides validate the FlatBuffers verifier/file identifier, schema major/minor, monotonic correlation header, and non-default payload fields. Unknown major versions and newer unsupported minor versions fail closed.

## 6. Generated Artifact Review Policy

- Modify `.fbs` sources, never generated files.
- Run generation, conformance, the native schema test, and the cross-language golden test in the same change.
- Add fields only at the end of a table and give them explicit safe defaults.
- Treat generated code as a third-party-derived artifact; its compiler version and license record are maintained under `LICENSES/`.
